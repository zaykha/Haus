## High-Level Shape

- `app/`
  - route entrypoints

- `components/`
  - screen-level UI for dashboard, projects, tasks, clients, team, profile
  - shared state lives in `components/app-state.tsx`
- `lib/`
  - types, permissions, navigation, display helpers, Supabase clients, image optimization
- `supabase/migrations/`
  - invitation system
  - RLS fixes

  - task completion screenshot support
  - task client-visibility support

## Core Nodes

- `components/app-state.tsx`
  - main client-side workspace state and Supabase orchestration
- `lib/types.ts`
  - shared domain model for users, projects, tasks, files, feedback, invitations
- `lib/permissions.ts`
  - role checks and task/project visibility rules
- `components/project-detail-screen.tsx`
  - deepest single screen; project overview, task management, latest version, feedback
- `components/tasks-screen.tsx`
  - global task table, designer task update flow, completion screenshot upload
- `components/dashboard-screen.tsx`
  - role-aware dashboard summaries and quick actions
- `app/api/workspace/projects/[id]/tasks/[taskId]/route.ts`
  - manager/designer task update endpoint

## Likely Architecture

1. App routes under `app/(app)/...` mount screen components.
2. Screen components consume `useAppState()` from `components/app-state.tsx`.
3. `app-state` reads and writes Supabase-backed workspace data.
4. Domain rules are centralized in `lib/permissions.ts` and `lib/types.ts`.
5. Manager, designer, and client experiences are mostly separated by visibility filters rather than separate codebases.

## Current Domain Model Highlights

- Users have roles:
  - `communication_manager`
  - `creative_manager`
  - `designer`
  - `client`
- Projects contain:
  - staff membership
  - tasks
  - files / versions
  - comments
  - feedback
- Tasks now also support:
  - `completionScreenshotUrl`
  - `clientVisible`
  - `managerReviewStatus`

## Important Recent Workflow

- Designers can update only their own assigned tasks.
- When designers complete a task, they can upload an optimized image proof.
- Managers review completed task output and decide whether to:
  - keep it internal
  - send it to client
  - request revision
- Client-facing task views should now be curated through task visibility instead of exposing all internal tasks.

- Default Supabase bucket name is `project-images`.
- Upload route expects `image/webp` and can be reused for task completion screenshots.
